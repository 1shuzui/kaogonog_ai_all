# 数据库内容与字段说明

更新时间：2026-06-09

本文用于核对当前后端数据库里“有哪些表、每张表保存什么、哪些 JSON 字段有业务含义”。内容依据当前代码中的 `civil-interview-backend/app/models/entities.py`、`civil-interview-backend/database_setup.py`、`civil-interview-backend/main.py` 和相关 service 整理。

注意：本次整理没有直接连接本地 MySQL 做 `DESCRIBE`，因为当前环境的数据库账号认证失败。下面以代码声明和建表脚本为准；生产库若由旧版本逐步迁移，可能额外存在 `updated_at` 这类建表脚本字段。

## 总览

当前核心 MySQL 表共 10 张：

| 表名 | 主要用途 | 关键业务 |
| --- | --- | --- |
| `users` | 用户账号、偏好、登录与活跃统计 | 登录、注册量、日活、练习偏好、微信绑定 |
| `questions` | 题库题目和套题元数据 | 专项练习、全真模拟、题库筛选、评分依据 |
| `exams` | 一次考试/练习会话 | 记录抽到哪些题、考试状态和起止时间 |
| `exam_answers` | 每道题的作答、转写和评分结果 | ASR 转写、评分结果、媒体记录 |
| `history_records` | 完成后的历史成绩快照 | 成绩趋势、薄弱维度、历史记录 |
| `subscription_packages` | 后台上架的套餐定义 | 虚拟支付道具、权益时长、每日限额 |
| `payment_orders` | 用户支付订单 | 微信小程序虚拟支付、查单、退款追踪 |
| `user_subscriptions` | 用户已获得的权益 | 剩余分钟数、试用状态、套餐有效期 |
| `usage_records` | 答题用时与扣量流水 | 扣减权益、排查“时长没扣” |
| `support_feedback` | 用户反馈与管理员处理记录 | 题目纠错、支付问题、体验建议 |
| `targeted_focus_configs` | 定向备面重点分析的管理员配置 | 管理员发布重点分析、覆盖自动分析 |

## 关系简图

```text
users.username
  ├─ payment_orders.username
  │    └─ user_subscriptions.source_order_no = payment_orders.order_no
  ├─ user_subscriptions.username
  ├─ usage_records.username
  ├─ history_records.username
  └─ support_feedback.username

exams.id
  ├─ exam_answers.exam_id
  ├─ history_records.exam_id
  └─ usage_records.exam_id

questions.id
  ├─ exams.question_ids(JSON 列表)
  ├─ exam_answers.question_id
  └─ usage_records.question_id
```

说明：

- `users.username` 是很多业务表的串联字段，虽然 `users.id` 是自增主键，但订单、权益、历史、用量仍主要按用户名关联。
- `exams.question_ids` 是 JSON 数组，不是外键；真实题目信息通过 `questions.id` 再查。
- `questions.keywords._meta` 承载大量套题与分类元数据，当前没有单独拆套题表，这是为了避免迁移风险。

## 表结构说明

### users

保存用户账号、登录状态、偏好和统计时间。管理员账号也是普通用户表中的一条记录，权限由鉴权层根据账号/配置判断。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键，主要给数据库内部使用。 |
| `username` | String | 登录账号，全局唯一；微信小程序自动账号通常类似 `wxmp_...`。 |
| `hashed_password` | String | 加密后的密码，不保存明文。 |
| `full_name` | String | 展示姓名/昵称。 |
| `email` | String | 邮箱或辅助联系方式。 |
| `avatar` | String | 头像地址。 |
| `province` | String | 用户默认地区/考试设置的旧口径字段，默认 `national`。 |
| `disabled` | Boolean | 是否禁用账号。 |
| `preferences` | JSON | 用户偏好、权益快照、微信绑定信息等。 |
| `agreed_terms_version` | String | 用户已同意的协议版本。 |
| `agreed_terms_at` | DateTime | 同意协议的时间。 |
| `last_login_at` | DateTime | 最近一次主动登录时间，用于登录统计。 |
| `last_active_at` | DateTime | 最近一次请求/活跃时间，用于日活统计。 |
| `last_login_device` | String | 最近登录设备摘要。 |
| `login_device_history` | JSON | 登录设备历史。 |
| `registered_at` | DateTime | 注册时间，用于新用户统计；旧用户会用 `created_at` 回填。 |
| `created_at` | DateTime | 记录创建时间。 |
| `updated_at` | Timestamp | 建表脚本中存在，ORM 未显式声明；用于生产库自动更新时间。 |

`preferences` 常见结构：

```json
{
  "defaultPrepTime": 90,
  "defaultAnswerTime": 180,
  "enableVideo": true,
  "enableAudio": true,
  "preferredQuestionDimensions": ["analysis"],
  "practicePreferenceConfirmed": true,
  "examCategory": "事业单位考试",
  "activeSubscriptionId": 12,
  "subscription": {
    "planType": "monthly",
    "planName": "包月套餐 1小时/天",
    "status": "active",
    "totalMinutes": 1800,
    "usedMinutes": 35,
    "dailyLimitMinutes": 60,
    "dailyUsedMinutes": 10,
    "remainingMinutes": 1765,
    "remainingDailyMinutes": 50,
    "packageCode": "monthly_1h_day"
  },
  "wechatMiniProgram": {
    "openId": "...",
    "unionId": "..."
  }
}
```

注意：

- `preferredQuestionDimensions` 是训练题型/练习偏好，不等同于能力雷达维度。
- `subscription` 是权益快照，真正扣量以 `user_subscriptions` 和 `usage_records` 为准。
- 活跃统计优先看 `last_active_at`，注册统计优先看 `registered_at`。

### questions

保存单题题干、评分依据、训练分类和真实套题元数据。题库导入脚本会把套题信息写入 `keywords._meta`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | String | 题目主键，例如 `JS-LYG-LYQ20250705_01` 或 `q001`。 |
| `stem` | Text | 题干正文。 |
| `dimension` | String | 训练分类/题型筛选键，如 `analysis`、`emergency`。 |
| `province` | String | 地区代码，如 `jiangsu`、`anhui`、`hunan`、`national`。 |
| `prep_time` | Integer | 读题/准备时间，单位秒。 |
| `answer_time` | Integer | 答题时间，单位秒。 |
| `scoring_points` | JSON | 采分点列表，用于评分提示和规则兜底。 |
| `keywords` | JSON | 得分关键词、扣分关键词、亮点关键词，以及 `_meta` 元数据。 |
| `created_at` | DateTime | 题目入库时间。 |
| `updated_at` | Timestamp | 建表脚本中存在，ORM 未显式声明。 |

`dimension` 当前常见训练分类键：

| key | 展示口径 |
| --- | --- |
| `analysis` | 综合分析 |
| `practical` | 组织管理/实务处理 |
| `emergency` | 应急应变 |
| `logic` | 人际沟通/逻辑组织，具体展示按前端场景变化 |
| `expression` | 情景模拟/语言表达，具体展示按前端场景变化 |
| `legal` | 岗位认知/职业认知；能力维度中对应“行政思维” |

`keywords` 基础结构：

```json
{
  "scoring": ["公共利益", "落地执行"],
  "deducting": ["空泛表态"],
  "bonus": ["结合地方实际"],
  "_meta": {}
}
```

`keywords._meta` 重要字段：

| 字段 | 含义 |
| --- | --- |
| `source` | 来源类型，如 `local_asset`、`imported_file`、`manual`、`ai_generated`。 |
| `sourceLabel` | 来源展示名，如“本地真题”。 |
| `sourceDocument` | 原始文档名。 |
| `originFile` | 资产文件路径或来源文件名。 |
| `sourceQuestionId` | 导入前的原始题号。 |
| `tags` | 标签列表。 |
| `positionTags` | 岗位/系统标签，如 `general`、`township`、`prison`、`medical`。 |
| `referenceAnswer` | 参考答案；主要用于回归/样例，不是新题评分的必填项。 |
| `scoreBands` | 分档评分说明。 |
| `regressionCases` | 回归测试样例。 |
| `coreKeywords` | 核心关键词。 |
| `strongKeywords` | 强相关关键词。 |
| `weakKeywords` | 弱相关关键词。 |
| `bonusKeywords` | 加分关键词。 |
| `penaltyKeywords` | 扣分关键词。 |
| `questionType` | 原始题型描述。 |
| `suiteId` / `suiteKey` | 套题唯一标识，用于全真模拟组卷。 |
| `suiteName` | 中文真实套题名，前端全真套题优先显示它。 |
| `sourceTitleRaw` | 原始标题，便于追溯。 |
| `examDate` | 考试日期。 |
| `year` | 年份列表，用于年份筛选。 |
| `position` | 岗位/方向文本。 |
| `batch` | 批次。 |
| `questionNo` | 套题内题号。 |
| `questionScore` | 单题分值。 |
| `answerScoreTotal` | 答题总分。 |
| `appearanceScore` | 仪态分；没有时不要默认展示仪态分提示。 |
| `hasAppearanceScore` | 是否确认存在仪态分。 |
| `suiteTotalScore` / `totalScore` | 套题总分。 |
| `examCategory` | 真实考试大类，如“事业单位考试”“省级公务员考试”。 |
| `examSubcategory` | 二级分类，如“江苏省”“安徽省”。 |
| `subcategory` | 三级分类，如地市、系统。 |
| `subcategory2` | 四级分类，如区县、具体单位。 |
| `interviewFormat` | 面试形式，如“结构化面试”“结构化小组”。 |
| `questionTypeCategory` | 题型分类，如“综合分析”“组织管理”。 |
| `jobLevel` | 岗位层级，如“省直”“市属”“乡镇基层”。 |
| `timingMode` | 时间模式说明。 |
| `questionCount` | 套题题量。 |
| `classificationSource` | 分类依据，如 `suite_title`、`source_title`。 |
| `classificationConfidence` | 分类置信度：`high`、`medium`、`low`。 |
| `reviewStatus` | 复核状态，如“已确认”“待确认”“需人工复核”。 |
| `reviewReason` | 需要复核的原因。 |
| `hasCompleteSuiteLevel` | 是否具备完整套题层级信息。 |

索引：

- `idx_questions_province_dimension(province, dimension)`
- `idx_questions_dimension_province(dimension, province)`

### exams

保存一次练习或考试会话。它不是最终成绩表，只记录“这次开始了什么题、状态如何”。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | String | 考试会话 ID，通常以 `exam_` 开头。 |
| `user_id` | String | 用户名；这里字段名叫 `user_id`，实际存 `users.username`。 |
| `question_ids` | JSON | 本次抽到的题目 ID 列表。 |
| `status` | String | 状态，如 `in_progress`、`completed`。 |
| `start_time` | DateTime | 开始时间。 |
| `end_time` | DateTime | 结束时间。 |
| `created_at` / `updated_at` | Timestamp | 建表脚本字段，用于记录创建和更新时间。 |

索引：

- `idx_exams_user_id(user_id)`

### exam_answers

保存每道题的答题文本、评分结果和媒体记录。ASR 转写结果最终落在 `transcript`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键。 |
| `exam_id` | String | 所属考试，外键到 `exams.id`。 |
| `question_id` | String | 题目 ID。 |
| `transcript` | Text/LongText | 答题文字稿，来自手输或 ASR。 |
| `score_result` | JSON | 评分结果完整 JSON。 |
| `media_record` | JSON | 上传音频/视频的记录。 |
| `answered_at` | DateTime | 作答提交时间。 |
| `created_at` / `updated_at` | Timestamp | 建表脚本字段。 |

`score_result` 常见字段：

| 字段 | 含义 |
| --- | --- |
| `totalScore` | 总分。 |
| `maxScore` | 满分。 |
| `grade` | 等级，如 A/B/C/D。 |
| `dimensions` | 能力维度得分列表。能力维度应使用“行政思维、实务落地、逻辑结构、语言表达、综合分析、应急应变”。 |
| `comments` / `summary` | 评语或总结。 |
| `suggestions` | 改进建议。 |
| `mediaRecord` | 有些旧结果会把媒体信息放在评分结果内。 |

`media_record` 常见字段：

| 字段 | 含义 |
| --- | --- |
| `fileUrl` | 媒体文件访问地址。 |
| `mediaType` | `audio` 或 `video`。 |
| `originalFilename` | 原始文件名。 |
| `source` | 上传来源。 |

约束：

- 建表脚本有 `UNIQUE KEY uq_exam_question(exam_id, question_id)`，同一场考试同一题只保留一份答案。
- `exam_id` 外键级联删除。

### history_records

保存完成考试后的历史成绩快照，用于历史列表、成绩趋势和薄弱维度。它避免每次打开历史页都重新汇总 `exam_answers`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键。 |
| `exam_id` | String | 考试 ID，唯一。 |
| `username` | String | 用户名。 |
| `question_count` | Integer | 本次计分题数。 |
| `total_score` | Float | 总分或平均分，按当前服务逻辑展示。 |
| `max_score` | Float | 满分，默认 100。 |
| `grade` | String | 等级，默认 B。 |
| `dimensions` | JSON | 能力维度得分快照。 |
| `province` | String | 地区筛选值。 |
| `completed_at` | DateTime | 完成时间。 |
| `created_at` / `updated_at` | Timestamp | 建表脚本字段。 |

`dimensions` 示例：

```json
[
  {"name": "行政思维", "score": 15, "maxScore": 20},
  {"name": "实务落地", "score": 16, "maxScore": 20}
]
```

注意：

- 历史服务会把旧的“法治思维”兼容显示为“行政思维”。
- `exam_id` 唯一，避免同一场考试重复进入趋势统计。

### subscription_packages

保存后台上架的套餐定义。套餐中心和微信虚拟支付道具应与这里的 `package_code` 对齐。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键。 |
| `package_code` | String | 套餐代码，唯一；也是支付道具映射的关键。 |
| `package_name` | String | 套餐展示名。 |
| `package_type` | String | 套餐类型，如 `hourly`、`monthly`、`premium`、`trial`。 |
| `price` | Numeric | 价格，单位元；虚拟支付实际金额可能按微信道具价格回写。 |
| `total_minutes` | Integer | 总可用分钟数。 |
| `daily_limit_minutes` | Integer | 每日可用分钟数，0 表示不限制。 |
| `duration_days` | Integer | 有效天数，0 表示不按日期过期。 |
| `is_active` | Boolean | 是否上架。 |
| `description` | String | 套餐说明。 |
| `extra_config` | JSON | 扩展配置。 |
| `created_at` / `updated_at` | Timestamp | 创建/更新时间。 |

当前 seed 套餐：

| package_code | 名称 | 类型 | 价格 | 总分钟 | 每日上限 | 有效期 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| `trial_3h` | 3小时套餐 | `hourly` | 99.00 | 180 | 180 | 0 天 |
| `monthly_1h_day` | 包月套餐 1小时/天 | `monthly` | 299.00 | 1800 | 60 | 30 天 |
| `monthly_2h_day` | 包月包 2小时/天 | `monthly` | 499.00 | 3600 | 120 | 30 天 |
| `premium_1000` | 高阶包月 1000元档 | `premium` | 1000.00 | 9000 | 300 | 30 天 |
| `premium_2000` | 高阶包月 2000元档 | `premium` | 2000.00 | 24000 | 800 | 30 天 |

### payment_orders

保存支付订单和微信虚拟支付查单、退款信息。当前默认支付渠道是 `wechat_virtual`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键。 |
| `order_no` | String | 内部订单号，唯一，退款和查单都以它追踪。 |
| `username` | String | 下单用户，外键到 `users.username`。 |
| `package_code` | String | 购买套餐。 |
| `package_type` | String | 下单时套餐类型快照。 |
| `amount` | Numeric | 订单金额；拉起虚拟支付后会按微信道具价格同步。 |
| `pay_channel` | String | 支付渠道，应为 `wechat_virtual`。 |
| `status` | String | 状态：`pending`、`paid`、`refunded` 等。 |
| `third_party_order_no` | String | 微信侧订单号/交易号。 |
| `paid_at` | DateTime | 支付成功时间。 |
| `callback_payload` | JSON | 支付确认、查单和退款结果。 |
| `extra_payload` | JSON | 下单时客户端、openId、虚拟支付环境等辅助信息。 |
| `created_at` / `updated_at` | Timestamp | 创建/更新时间。 |

`extra_payload` 常见字段：

```json
{
  "packageName": "3小时套餐",
  "scene": "mini_program_virtual",
  "openId": "用户小程序 openId",
  "clientIp": "客户端 IP",
  "idempotencyKey": "端侧幂等键",
  "virtualPayEnv": 1,
  "virtualProductId": "trial_3h"
}
```

`callback_payload` 常见字段：

| 字段 | 含义 |
| --- | --- |
| `confirm` 或原始 `rawResult` | 端侧支付完成后回传的结果。 |
| `verified` | 是否经微信查单确认。 |
| `verifyPending` | 查单未确认或暂时失败。 |
| `verifyError` | 查单失败原因。 |
| `verifiedAt` | 查单时间。 |
| `queryResult` | 微信查单原始结果。 |
| `queryRequest` | 微信查单请求摘要。 |
| `refund` | 退款信息，包括退款小时、金额、微信退款订单号和原始返回。 |

索引：

- `idx_po_username_created(username, created_at)`
- `idx_po_status_created(status, created_at)`
- `idx_po_package_code(package_code)`

### user_subscriptions

保存用户真实可用权益。支付成功后会按订单创建一条权益；试用也会在这里创建一条 `is_trial=true` 的权益。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键。 |
| `username` | String | 用户名，外键到 `users.username`。 |
| `package_code` | String | 来源套餐代码。 |
| `plan_type` | String | 权益类型，如 `trial`、`hourly`、`monthly`。 |
| `plan_name` | String | 展示名。 |
| `status` | String | `active`、`inactive`、`refunded` 等。 |
| `is_trial` | Boolean | 是否试用权益。 |
| `trial_completed` | Boolean | 试用是否完成。 |
| `total_minutes` | Integer | 总分钟数。 |
| `used_minutes` | Integer | 已使用分钟数。 |
| `daily_limit_minutes` | Integer | 每日上限。 |
| `daily_used_minutes` | Integer | 今日已使用分钟数。 |
| `last_reset_date` | Date | 每日用量重置日期。 |
| `start_at` | DateTime | 权益开始时间。 |
| `end_at` | DateTime | 权益过期时间。 |
| `source_order_no` | String | 来源订单号；试用或自动创建时可为空。 |
| `extra_payload` | JSON | 支付渠道、退款、自动创建等附加信息。 |
| `created_at` / `updated_at` | Timestamp | 创建/更新时间。 |

扣量规则：

- `usage_records` 记录每次上报；同时累加到 `used_minutes` 和 `daily_used_minutes`。
- 上报秒数按分钟向上取整：例如 61 秒计 2 分钟。
- 当 `used_minutes >= total_minutes`，权益会被标记为 `inactive`。
- 包月权益每日限额依赖 `last_reset_date` 自动重置。

### usage_records

保存每次使用权益的流水，是排查扣量最重要的表。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键。 |
| `username` | String | 用户名，外键到 `users.username`。 |
| `exam_id` | String | 考试 ID，外键到 `exams.id`。 |
| `question_id` | String | 题目 ID，可为空。 |
| `usage_type` | String | 使用场景，如 `practice`。 |
| `usage_seconds` | Integer | 端侧上报的秒数。 |
| `billed_minutes` | Integer | 实际扣减分钟数。 |
| `reported_at` | DateTime | 上报时间。 |
| `extra_payload` | JSON | 附加信息，如 `reportedMinutes`。 |
| `created_at` / `updated_at` | Timestamp | 创建/更新时间。 |

排查建议：

- 用户说“时长没有扣”：先看该用户最近 `usage_records` 是否有记录，再看对应 `user_subscriptions.used_minutes` 是否累加。
- 如果有多个可用权益，系统会优先使用用户偏好的 `activeSubscriptionId`，否则优先可用付费权益。

### support_feedback

保存用户反馈、附件和管理员处理记录。普通用户只能看自己的反馈，管理员可按 scope 查看全站。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键。 |
| `username` | String | 提交用户。 |
| `feedback_type` | String | 类型，如题目纠错、支付问题、其他建议。 |
| `question_id` | String | 关联题目 ID，可为空。 |
| `summary` | Text | 反馈正文。 |
| `contact` | String | 联系方式。 |
| `route_path` | String | 提交反馈时所在页面。 |
| `province` | String | 地区筛选。 |
| `status` | String | `pending` 或 `handled`。 |
| `admin_note` | Text | 管理员备注。 |
| `handled_by` | String | 处理人。 |
| `handled_at` | DateTime | 处理时间。 |
| `attachments` | JSON | 附件列表。 |
| `created_at` | DateTime | 创建时间。 |
| `updated_at` | DateTime | 更新时间。 |

`attachments` 示例：

```json
[
  {
    "storageKey": "support-feedback/xxx.png",
    "filename": "截图.png",
    "url": "/uploads/support-feedback/xxx.png",
    "size": 123456,
    "mimeType": "image/png",
    "uploadedAt": "2026-06-09T12:00:00+00:00"
  }
]
```

附件限制：

- 仅允许图片：jpg、png、webp、gif。
- 单个附件最大 5MB。
- 单条反馈最多 8 个附件。

### targeted_focus_configs

保存管理员发布的定向备面重点分析。普通用户调用重点分析时，如果有启用的管理员配置，会优先返回它；否则按真实题库自动统计。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | Integer/BigInt | 自增主键。 |
| `target_key` | String | 唯一目标键，通常由考试体系、地区、方向等组合而来。 |
| `target_code` | String | 分类树节点代码。 |
| `target_name` | String | 分类展示名。 |
| `province` | String | 地区代码。 |
| `position` | String | 岗位/方向代码。 |
| `payload` | JSON | 管理员发布的重点分析内容。 |
| `enabled` | Boolean | 是否启用。 |
| `updated_by` | String | 最近修改管理员。 |
| `created_at` / `updated_at` | Timestamp | 创建/更新时间。 |

`payload` 常见结构：

```json
{
  "focusAreas": [
    {
      "type": "行政思维",
      "dimensionKey": "legal",
      "label": "行政思维",
      "description": "注意依法行政、程序意识与公共治理表达。",
      "priority": "high",
      "questionCount": 12
    }
  ],
  "coreFocus": [
    {"name": "行政思维", "weight": 30, "desc": "重点训练规则意识"}
  ],
  "highFreqTypes": [
    {"name": "综合分析", "ratio": 42, "questionCount": 20}
  ],
  "hotTopics": ["基层治理", "公共服务"],
  "strategy": ["先按真实套题练习，再补弱项。"],
  "questionCount": 48,
  "dataSource": "admin_config",
  "isFallback": false
}
```

注意：

- `coreFocus` / `focusAreas` 表达考生答题能力重点。
- `highFreqTypes` 表达题型分类，不能混入“行政思维、实务落地”等能力维度。
- 无题库数据且无管理员发布时，普通用户应看到“暂无足够题库数据”，不能展示伪分析。

## 重要非表属性

### 数据库连接

配置入口：

- 优先读取 `DATABASE_URL`。
- 没有 `DATABASE_URL` 时拼接 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_DATABASE`。
- 兜底为 `sqlite:///./civil_interview.db`，主要用于本地或测试，不是线上推荐。

SQLAlchemy 连接：

- MySQL 开启 `pool_pre_ping=True`，避免连接池拿到断开的连接。
- MySQL 设置 `pool_recycle=1800`，减少长连接被服务端回收后的错误。
- SQLite 测试环境会启用 WAL 和外键。

### 初始化与补字段

启动流程会执行：

1. `Base.metadata.create_all(bind=engine)` 创建 ORM 声明的表。
2. `ensure_user_activity_schema()` 补齐 `last_login_at`、`last_active_at`、`registered_at` 和索引。
3. `ensure_question_indexes()` 补齐题库组合索引。
4. `ensure_targeted_focus_config_schema()` 补齐定向备面配置字段和唯一索引。
5. 同步套餐 seed 和本地题库资产。

`database_setup.py` 也提供独立建库/补字段脚本，适合新服务器初始化或旧库补字段。

### Redis 缓存键

Redis 不属于 MySQL 表，但会影响数据读取表现：

| key 模式 | 内容 | 默认 TTL |
| --- | --- | --- |
| `question:{id}` | 单题 JSON | `REDIS_CACHE_TTL_QUESTIONS`，默认 3600 秒 |
| `questions:index:all` | 全部题目 ID 列表 | 默认 3600 秒 |
| `questions:by_province:{province}` | 按省份题目 ID | 默认 3600 秒 |
| `questions:by_dimension:{dimension}` | 按训练分类题目 ID | 默认 3600 秒 |
| LLM 评分缓存 key | 重复评分结果 | `REDIS_CACHE_TTL_LLM`，默认 86400 秒 |
| ASR 转写缓存 key | 音频转写文本 | `REDIS_CACHE_TTL_TRANSCRIPT`，默认 3600 秒 |

题库修改、导入、同步后应清理相关题库缓存，否则前端可能短时间看到旧题或旧套题名。

### 题库分类口径

当前题库分类要同时保存几套概念：

- `examCategory`：真实考试大类，例如国家公务员考试、省级公务员考试、事业单位考试。
- `examSubcategory`：二级分类，例如江苏省、安徽省、中央国家行政机关。
- `province/city/district` 或 `subcategory/subcategory2`：地区或层级。
- `system/agency/positionType/jobLevel/interviewFormat`：系统、单位、岗位、层级、面试形式。
- `questionTypeCategory`：题型分类，例如综合分析、组织管理、应急应变、人际沟通、情景模拟、岗位认知。
- 能力维度：评分和薄弱分析使用“行政思维、实务落地、逻辑结构、语言表达、综合分析、应急应变”。

不要把“省份”当成考试体系，也不要把题型分类当成岗位分类。

## 常用核对 SQL

以下 SQL 只用于排查结构和统计，不输出敏感内容：

```sql
-- 看所有表记录数
SELECT 'users' AS table_name, COUNT(*) AS cnt FROM users
UNION ALL SELECT 'questions', COUNT(*) FROM questions
UNION ALL SELECT 'exams', COUNT(*) FROM exams
UNION ALL SELECT 'exam_answers', COUNT(*) FROM exam_answers
UNION ALL SELECT 'history_records', COUNT(*) FROM history_records
UNION ALL SELECT 'subscription_packages', COUNT(*) FROM subscription_packages
UNION ALL SELECT 'payment_orders', COUNT(*) FROM payment_orders
UNION ALL SELECT 'user_subscriptions', COUNT(*) FROM user_subscriptions
UNION ALL SELECT 'usage_records', COUNT(*) FROM usage_records
UNION ALL SELECT 'support_feedback', COUNT(*) FROM support_feedback
UNION ALL SELECT 'targeted_focus_configs', COUNT(*) FROM targeted_focus_configs;

-- 今日活跃用户
SELECT COUNT(*) AS active_users_today
FROM users
WHERE last_active_at >= CURDATE()
  AND last_active_at < CURDATE() + INTERVAL 1 DAY;

-- 今日新注册用户
SELECT COUNT(*) AS new_users_today
FROM users
WHERE registered_at >= CURDATE()
  AND registered_at < CURDATE() + INTERVAL 1 DAY;

-- 今日支付成功订单
SELECT COUNT(*) AS paid_orders_today, COALESCE(SUM(amount), 0) AS paid_amount_today
FROM payment_orders
WHERE status = 'paid'
  AND paid_at >= CURDATE()
  AND paid_at < CURDATE() + INTERVAL 1 DAY;

-- 某用户权益与扣量
SELECT id, package_code, plan_type, status, total_minutes, used_minutes,
       daily_limit_minutes, daily_used_minutes, last_reset_date, start_at, end_at
FROM user_subscriptions
WHERE username = '替换成用户名'
ORDER BY created_at DESC, id DESC;

SELECT exam_id, question_id, usage_type, usage_seconds, billed_minutes, reported_at
FROM usage_records
WHERE username = '替换成用户名'
ORDER BY reported_at DESC, id DESC
LIMIT 20;

-- 题库套题元数据抽查
SELECT id,
       JSON_UNQUOTE(JSON_EXTRACT(keywords, '$._meta.suiteName')) AS suite_name,
       JSON_UNQUOTE(JSON_EXTRACT(keywords, '$._meta.examCategory')) AS exam_category,
       JSON_UNQUOTE(JSON_EXTRACT(keywords, '$._meta.examDate')) AS exam_date,
       JSON_UNQUOTE(JSON_EXTRACT(keywords, '$._meta.questionNo')) AS question_no
FROM questions
WHERE province = 'jiangsu'
ORDER BY id
LIMIT 20;
```

## 维护风险点

- 改 `users.username` 风险很高：订单、权益、历史、反馈等表都按它关联。
- 改 `questions.id` 风险很高：考试、答案、历史详情都依赖题目 ID。
- `questions.keywords._meta` 是当前套题和分类元数据的主要承载位，导入脚本、全真模拟、定向备面都会读取它。
- 新题不一定需要参考答案，但至少应保证题干、训练分类、采分点、关键词和套题元数据尽量完整；采分点太少会让评分更依赖通用模型。
- 微信虚拟支付订单必须保留 `openId`、`virtualProductId`、`third_party_order_no` 和查单/退款原始结果，方便审核和退款排查。
- `updated_at` 在建表脚本里有，在 ORM 里不一定声明；写 ORM 查询时不要默认所有模型实例都有这个属性。
