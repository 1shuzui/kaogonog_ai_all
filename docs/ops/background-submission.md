# 考生端后台提交与恢复

更新：2026-09-19。适用于 PC 与微信考生端；管理员、支付、题库分值和所有权校验保持原有逻辑。

## 用户看到的流程

1. 点击“提交并继续”时，先固定本题的答题用时，仅等待本机录音停止、文件交付。
2. 本机拿到录音后立即进入下一题。上传、转写、点评由考试 store 的异步任务继续执行；使用时长上报也不阻塞换题。
3. 最后一题提交后立即进入结果页。先发完成请求固定服务器结束时间，后台任务完成后再刷新同一场次的历史汇总。
4. 有有效评分才显示分数；没有评分显示待点评/可重试。真实 0 分与“尚未取得评分”分开处理。
5. 结果页首先展示可用的原文；后台完成时刷新该题结果，不强行切走用户正在查看的题。

“后台”指客户端会话内的队列，并非已经部署了独立持久任务服务。不承诺关闭页面、清理小程序或退出账号后仍能完成上传。PC 有离开页面提醒，两端均显示保留页面/小程序的提示。

## 计时与重试边界

- 网络上传、ASR 和模型耗时不锁住下一题；只有停止本机录音、整理文件的强制短等待冻结计时。
- PC 倒计时按绝对截止时间计算，暂停/继续保留小数秒；微信定时器延迟时会补扣真实经过时间。
- 江苏 5+15 模式切题不重新开始 15 分钟；保留既有总时限与各模式时间规则，不用后台点评耗时延长作答额度。
- 同一场次、同一题重复点击只产生一个任务。失败时保留本次媒体和已取得的文字稿。
- 已上传的媒体不重复上传；已有有效原文时重试直接点评，不再次转写。费用与等待策略维持宽松默认。
- 同一账号开始新场次时，上一场内容暂存在内存；有未完成答案时保留整场媒体，首页、准备页、考场和结果页均可见待处理任务与重试入口。该场全部处理完成后，在下次成功开考时释放媒体引用，原文与点评保留至会话清理，避免正在查看的旧场结果消失。
- 新场创建失败，不清空旧场录音和答案。退出/换账号会清理归档，异步回调和 ASR 自动重试检查会话，不能把上一位用户的内容发送到下一位用户的身份下。

## 实现入口

- 两端 `src/stores/exam.js`：任务去重、分阶段处理、结束汇总、会话归档与隔离。
- `pendingAnswers`：当前登录会话所有未完成/失败答案；返回原始响应式对象。
- `getAnswersForExam(examId)`：当前与归档场次的本地答案，按题序排列，不发网络请求；未知场次返回空数组。
- `retryAnswer(answer)`：只接受该 store 当前持有的答案对象，拒绝已清理/其他会话对象。
- PC `StandardExamRoom.vue` / `FullExamRoom.vue`、微信 `pages/exam/room.vue`：整理本机录音后换题，不等待网络。
- 两端 `BackgroundAnswers.vue`：按阶段展示任务、失败重试与旧场次原文入口。
- 两端 `submissionProgress.js`：只根据已确认的处理状态展示三阶段进度；不伪造百分比。评分响应在归一化前检查有效数值，空值、空白和非有限分数转为可重试失败，数值 0 有效。
- PC `useCountdown.js`：截止时间与暂停精度；结果页 `answerStatus` 检查有效评分。

## 视觉与素材

核心四页采用明亮蓝色、青绿反馈和浅色工作区；管理员样式不参与。全真考场仍保留引导语及可展开的模拟场景，优先让题目、计时与录音控件占据空间。

字体使用中文系统字体，不从境外字体 CDN 加载。微信使用随包发布的 16 个 Ant Design outlined 图标；来源和 MIT 授权在 `src/static/learner-icons/`。再生成命令：`node scripts/export_learner_icons.mjs`，依赖 PC 已安装的图标包，不增加 npm 依赖。

设计规范见仓库根目录 `design.md`。Pencil 设计稿包含电脑四页、微信四页、规范及可编辑图标/状态组件，所有例题与状态均标注“设计演示”，不是线上成绩凭证。

## 点评速度与费用注意事项

继续使用 `LOCAL_REFERENCE_SCORING=false`。此轮消除了前台被迫等待，没有声称外部模型推理本身从 40–60 秒缩短为瞬时。模型费用和反馈内容不降级；继续复用已有评分缓存，并通过去重及跳过重复 ASR 减少无意义调用。以后若需要离开应用仍自动完成任务，再单独评估服务器持久队列与断点上传，不在当前版本虚构这项能力。
