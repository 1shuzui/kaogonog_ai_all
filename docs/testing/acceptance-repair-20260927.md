### 实际联调发现的兼容问题

- 新复习表与旧答案表在生产 MySQL 使用不同文本排序规则，跨表文本 JOIN 曾使复习查询返回 500。查询现先限定当前用户的考试答案，再批量读取题目和复习状态按精确 ID 关联，避免变更既有数据库列的排序规则。修正后已在真实数据库及鉴权 HTTP 接口复验。
- 用独立账号和已审计的人工补发权益进行 PC 选题时发现：服务端返回 `isPaid: true`，PC 只按套餐名称识别权限，将 `manual` 归为试用并阻断准备页。PC 现使用服务端明确的权限快照，保留期限及总量／每日额度检查；旧接口无权限字段时继续兼容原按时／包月规则。小程序缓存同时保留服务端明确的 `false`，避免被套餐名称再次推定为开通。新增 8 项回归在修复前复现其中 3 个失败，修复后全部通过。
